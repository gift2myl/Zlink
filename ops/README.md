# 家庭智能运维管家 · 官网演示发布说明

## 当前版本 v1.4 · 2026-11-20

### 本次任务与实现

用户要求根据《心舍3.0.1灵之解决方案简介》的设备型号与配置规则匹配三维户型，在户型中呈现设备及整屋异常，并持续收录自如北京地图「更多 → 灵之智能」的房源，按商圈、居室管理。本版将**官方房源与户型证据、文档配置规划、运行状态**分开建档，避免以规则推演替代实装清单或真实遥测。

- 新增设备配置目录与纯规则模块：25个型号族／规格条目、22张PDF原产品参考图；支持基础、Plus、升级选配三种规划。
- 已为全部10条采集记录保存逐套、逐方案的设备配置规划台账；按房间、设备型号、文档页码追溯，安装数量与遥测保持未知。
- 三维参考房源按配置清单生成设备层，点击设备或热点可查看型号、空间和规则出处；按设备形态呈现网关、面屏、灯、门锁、传感器、窗帘等。
- 异常演示区分「配置状态」「网关离线」「单灯异常」「安全告警」。状态同时作用于设备标记、房间地面和整屋摘要；未接入真实状态时不自动判为正常。
- 网关离线演示只标出链路影响，其余设备显示远程状态待核验；安全情景若当前配置不包含传感器，返回情景不可用，不新增虚构设备。
- 其余9条缺少对应户型资料的房源可查看配置规划与资料缺口，**不将唯一样板投射到其他房源，不把通用结构算作真实户型完成数**。

### Scrapling采集与离线流水线

当前Scrapling 0.5.1的Selector解析能力已可用；原生Fetcher仍缺少`patchright`依赖，不能将已安装解析器描述为已完成动态全站抓取。`tools/collect_ziroom_lingzhi.py`提供公开响应检查、显式字段映射的`adapt-html`／`adapt-json`离线转换，以及用Scrapling Selector检查已保存官方HTML中真实出现的详情、户型图、VR链接。发现链接不等于已下载素材或已完成三维重建。

增量采集优先按真实房源ID或实际详情URL合并，零新增不清空历史；即使后续批次宣称完整，也保留已收录历史记录。全量标记必须同时具备北京全城范围、灵之筛选、完整分页、精确总量和可靠身份，单个地图视窗总数不能标为全北京全量。`tools/build_inventory_registry.py`据持久数据生成房源注册表和来源状态。

**本轮实际网络请求0，新增房源0。** 沿用最近原地图访问记录：2026-11-20 **10:55:06（北京时间）**，访问校验页阻断；流水线保留该状态并阻止无进展的重复联网，没有使用验证Cookie、指纹伪装或替代端点。已测试的离线fixture均为临时测试数据，不进入正式台账。取得正常官方响应或授权导出的真实页面／结构化数据后可继续接入；需要逐套对应户型图／VR和实装台账，才能推进剩余9套真实空间与生产设备状态。

现有家庭运行的旧七设备固定演示归档继续单独保留，不与本版3.0.1配置清单混作实装证据。网站仍为演示应用，不具备生产设备控制、真实派单或已经持续抓取全北京房源的能力。

### 家庭运行：四步、六维、规则问答

家庭工作区按「**家庭入口 → 运行看板 → 运行详情 → 问题承接**」组织；六个运行维度为「**连接、执行、联动、安防、耗材、使用**」。从维度可继续查看关联设备、来源口径、待核验证据和已有待办，再进入诊断、工单草稿与模拟复验。

「灵之百晓生」当前提供**本地规则匹配的演示问答**，可围绕“为什么异常”“怎么办”“以前处理过吗”使用当前房源、维度、窗口、事件与当前浏览器工单上下文。回答按“观察到什么、原因候选、建议核验、下一步与复验”展开，保留提问时上下文。未接入大模型、真实设备遥测或外部维修历史，不具备开放域推理、真实设备控制或实际派单能力；未知事实继续显示未知。
