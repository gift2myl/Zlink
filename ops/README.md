## 家庭运行：四步、六维、规则问答

家庭工作区按「**家庭入口 → 运行看板 → 运行详情 → 问题承接**」组织；六个运行维度为「**连接、执行、联动、安防、耗材、使用**」。从维度可继续查看关联设备、来源口径、待核验证据和已有待办，再进入诊断、工单草稿与模拟复验。

「灵之百晓生」当前提供**本地规则匹配的演示问答**，可围绕“为什么异常”“怎么办”“以前处理过吗”使用当前房源、维度、窗口、事件与当前浏览器工单上下文。回答按“观察到什么、原因候选、建议核验、下一步与复验”展开，保留提问时上下文。未接入大模型、真实设备遥测或外部维修历史，不具备开放域推理、真实设备控制或实际派单能力；未知事实继续显示未知。

只有 **810151211** 使用七设备固定演示数据（fixture `HH-DEMO-20261119-v1`）：网关、照明、空调、门锁、烟感、漏水传感器和窗帘驱动。它们用于演示运行分析，不是该摄影房源的实际安装清单或生产设备绑定。

模拟复验只更新当前浏览器的演示待办、工单及当前演示状态，**不改写固定归档，不让历史日/周/月指标随复验变成 100%，也不改写已经生成的问答上下文**。现场真实状态没有因此发生变化。

## 后续补齐方式

取得用户授权提供的公开房源清单或正常可访问的官方来源后，先核验每条的真实房源 ID、详情链接、城市、明确出租方式、灵之智能证据、小区、行政区、商圈、整套居室数及来源时间，再更新逐条核验台账。不同来源必须按真实 ID 去重，未知字段保留未知；只有满足新口径的记录才进入首页统计和默认地图。浏览器 CSV 导入仍只增加本地演示台账，不自动变成已核验库存。

要补齐其余 9 套三维资料，需要每套独立对应的真实详情身份、户型图及主要室内空间照片，并保留文件与房源的关联和来源时间。若目标升级为尺寸可靠的工程模型，再补现场测量、层高、墙体、门窗与设备位置资料。单有房源行、站点坐标或楼盘名称，不能自动生成该套真实户型。

真实家庭运行接入需另有可核验的房源—设备绑定、带时间戳的遥测与执行回执、规则版本和工单记录。接入前维持当前演示归档与未知状态，不用运维截图或模拟复验补造生产数据。

本版本仍为静态演示，没有新增共享后台、访客端持续抓取或定时采集任务。部署链路和旧版变更记录保留如下。

### 北京房源采集接入

采集目标为自如公开地图北京（110000）“更多→灵之智能→确定”的可租房源。当前地图 URL 不保存筛选状态，不能仅凭 URL 或 HTTP 200 判断筛选完成。

本地已安装 Scrapling 0.5.1 解析组件。原生 Fetcher 所需额外浏览器相关依赖安装被自动审批拒绝，因此本版本通过普通 HTTP 传输配合 Scrapling 解析；不使用 StealthyFetcher、挑战破解、代理轮换或自动浏览器。

- `ops/assets/crawl-status.json` 保存本次安装能力、目标范围、抓取时间、有效页数、记录数与终止原因。
- `ops/assets/crawled-properties.json` 保存核验过筛选证据的采集结果。安全校验响应不计为成功列表页；空结果或失败不会替换原 `properties.json` 的历史样本。
- `ops/tools/` 提供可复用采集脚本及依赖说明。脚本只在普通访问可用、筛选和分页有来源证据时收录数据；当前自如地图的 JavaScript 安全校验阻断了全量采集，未取得全量明细。
- 房源台账按 24 条分页，保留公开快照、采集批次和浏览器本地 CSV 的来源区别。公开记录优先，房源 ID 统一为字符串；搜索和区域筛选会重置分页。
- 新收录房源不会自动获得三维模型、真实遥测或房屋精确坐标。现有三维样板仍只对应 810151211。

本网站为静态演示。采集脚本在受控执行环境中运行并产出数据文件，网站展示最近一次提交的结果；没有在访客浏览器中持续抓取，也没有创建定时采集任务。
